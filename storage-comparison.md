# Сравнение вариантов хранения модулей в Terralist

## Вариант 1: Только PVC (ваш текущий)

### Плюсы:
- ✅ Простота - не нужно настраивать S3
- ✅ Все в одном месте
- ✅ Нет дополнительных затрат на S3
- ✅ Быстрый доступ к файлам (локальный диск)
- ✅ Работает для небольших команд и проектов

### Минусы:
- ❌ Ограничен размером PVC
- ❌ Нет географической репликации
- ❌ Сложно масштабировать
- ❌ При потере PVC теряются и модули
- ❌ Нельзя использовать CDN
- ❌ Backup сложнее

### Подходит для:
- Небольших команд (до 10-20 человек)
- Внутренних проектов
- Когда модулей немного (до 100)
- Proof of Concept

## Вариант 2: PVC + S3

### Плюсы:
- ✅ Неограниченное хранилище
- ✅ Географическая репликация
- ✅ Легко делать backup
- ✅ Можно использовать CDN
- ✅ Масштабируемость
- ✅ Стандарт индустрии

### Минусы:
- ❌ Дополнительные расходы
- ❌ Сложнее настройка
- ❌ Зависимость от S3
- ❌ Немного медленнее доступ

### Подходит для:
- Средних и больших команд
- Production окружений
- Публичных registry
- Когда важна надежность

## Рекомендации:

### Для начала (ваш случай):
```yaml
# Можно начать без S3
persistence:
  enabled: true
  size: 10Gi  # Увеличьте если нужно

# S3 пока отключен
config:
  s3:
    enabled: false
```

### Когда пора переходить на S3:
1. PVC заполнился более чем на 70%
2. Модулей стало больше 50-100
3. Нужен доступ из разных регионов
4. Требуется надежный backup
5. Планируется публичный доступ

### Миграция на S3 (когда понадобится):
```yaml
config:
  s3:
    enabled: true
    endpoint: "s3.amazonaws.com"
    bucketName: "company-terralist-modules"
    bucketRegion: "eu-central-1"
    accessKeyId: "xxx"
    secretAccessKey: "yyy"
```

## Мониторинг использования PVC:

```bash
# Проверка использования диска
kubectl exec -n terralist terralist-0 -- df -h /mnt/data

# Алерт при заполнении на 80%
kubectl exec -n terralist terralist-0 -- sh -c \
  'used=$(df /mnt/data | tail -1 | awk "{print \$5}" | sed "s/%//"); \
   if [ $used -gt 80 ]; then echo "WARNING: PVC is $used% full!"; fi'
```

## Вывод:

Для вашего случая **PVC без S3 - это нормально**, если:
- У вас немного модулей (< 100)
- Это внутренний registry
- Размер модулей небольшой
- Есть backup стратегия для PVC

Когда начнете активно использовать и модулей станет много - тогда стоит добавить S3.
